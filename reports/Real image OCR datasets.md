# Choose hard real-image OCR benchmarks

**Yes—PaddleOCR and RapidOCR can both be built and compared, but the comparison has two meanings.** RapidOCR packages inference runtimes for PaddleOCR-derived models, so matching model files often make the first comparison a runtime/conversion parity test, not an independent contest between trained OCR systems; verify checkpoint and dictionary hashes. To compare model quality, also test demonstrably different detector/recognizer weights under a controlled pipeline. For difficult real-image text, prioritize ICDAR 2015 for incidental capture, TextOCR for dense clutter, Total-Text for curved words, and TextZoom for genuinely low-resolution recognition; add multilingual MLT or Chinese ReCTS/LSVT only when those scripts matter. No one public dataset spans all relevant failures, and none substitutes for a permissioned Czech–English camera set. Keep detection, fixed-crop recognition, and end-to-end spotting results separate, and check each dataset’s access and image-use terms before downloading, redistributing, or using it commercially. ([PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR); [RapidOCR](https://github.com/RapidAI/RapidOCR); [Baek et al., scene-text comparison protocol](https://arxiv.org/abs/1904.01906))

## Shared upstream weights make two comparisons necessary

Both projects are buildable open-source software: PaddleOCR is the upstream OCR toolkit, while RapidOCR focuses on deploying converted models through runtimes such as ONNX Runtime, OpenVINO, MNN and others. RapidOCR documents PaddleOCR model derivation, so overlapping weights are expected, but the relationship must be established for the exact detector, recognizer, vocabulary and release—not inferred from project names. Record model files and SHA-256 hashes, package versions and preprocessing/postprocessing settings. ([PaddleOCR repository](https://github.com/PaddlePaddle/PaddleOCR); [RapidOCR repository and model notes](https://github.com/RapidAI/RapidOCR))

Run a **matched-weight track** first: feed the same images through the same detector–recognizer pair with equivalent resize, thresholds, crop rectification, orientation handling and decoding. This measures export fidelity, numerical/runtime behavior and implementation differences. Then run an **out-of-box track** using each pinned project’s documented recommended models and defaults; that answers which deployable package works better in practice, but model differences are part of the result. Only compare intrinsic model quality when checkpoints are demonstrably different and the evaluation conditions are controlled. Measure accuracy and runtime separately on the same hardware, reporting cold start, steady-state latency and memory alongside paired predictions. ([RapidOCR](https://github.com/RapidAI/RapidOCR); [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR); [Baek et al.](https://arxiv.org/abs/1904.01906))

## Four datasets cover the most useful failure modes

| Priority | Dataset | What it tests and annotation/task | Practical caveat |
|---|---|---|---|
| Core | [ICDAR 2015 incidental scene text](https://rrc.cvc.uab.es/?ch=4) | Handheld, poorly framed scene text: rotation, perspective, blur, small text and clutter. Word-level quadrilaterals and transcriptions support detection and end-to-end evaluation. | English-dominated, relatively small, and challenge access/test-label rules apply. Confirm current portal conditions and evaluator. |
| Core | [TextOCR](https://textvqa.org/textocr/) | Dense everyday scenes with word-level transcriptions and tight regions; useful for recognition crops and full-image detection/spotting in clutter. | English and COCO-derived; annotation conventions differ from detector benchmarks, so adapt carefully and do not assume every text instance has equivalent labels. |
| Core | [Total-Text](https://github.com/cs-chan/Total-Text-Dataset) | Natural-image horizontal, multi-oriented and curved English words, with polygons and transcriptions; directly exposes geometry and crop-rectification failures. | Small; inspect polygon/evaluator conventions. Repository states BSD-3-Clause for project material but says commercial use requires contacting the author; code terms do not automatically clear image rights. |
| Diagnostic | [TextZoom](https://github.com/WenjiaWang0312/TextZoom) | Paired real-camera low/high-resolution word crops with case-sensitive transcription, for low-resolution recognition and optional super-resolution analysis. | Crops rather than full scenes, so it cannot evaluate localization. Download is hosted externally; the repository is not itself a blanket image-use license. |

This compact shortlist balances a scene-level incidental-capture test, broad dense-scene annotation, curved geometry and optical low resolution. [COCO-Text](https://bgshih.github.io/cocotext/) is a useful optional broad-context complement, but legibility and transcription availability vary. For a curved-text-heavy application, add [CTW1500](https://github.com/Yuliang-Liu/Curve-Text-Detector) or [ArT](https://github.com/zhangxinsong-nlp/ArT); CTW1500 is principally geometry/detection-focused and marks Chinese text as ignore in updated annotations, while ArT’s release details and terms should be checked directly. For multilingual coverage, add [ICDAR MLT-17](https://rrc.cvc.uab.es/?ch=8) or MLT-19; for Chinese, [ReCTS](https://rrc.cvc.uab.es/?ch=12) or [LSVT](https://rrc.cvc.uab.es/?ch=16) provide real signage, but their scripts and evaluation conventions make them a separate language panel. Dataset counts, transcription availability and access can vary by release; use official annotations and evaluators. ([COCO-Text project/API](https://bgshih.github.io/cocotext/); [TextZoom paper](https://arxiv.org/abs/2005.03341); [CTW1500 repository](https://github.com/Yuliang-Liu/Curve-Text-Detector))

## Evaluate localization, reading and the complete pipeline separately

Use three tasks so failures are attributable: **detection** scores predicted regions against the dataset’s official boxes/polygons; **recognition-only** runs both recognizers on identical ground-truth crops; **end-to-end spotting** scores localization and transcription together. Report official detection/end-to-end metrics when available, plus word-level precision, recall and F-score under a declared matching rule. On fixed crops report character error rate (CER), normalized edit distance and exact-word accuracy. State text normalization, case and punctuation policy, ignored/illegible-region handling, lexicon use, charset, input resizing, thresholds and model versions. Preserve Czech accents in primary scoring; show case- or accent-insensitive results only as secondary diagnostics. ([ICDAR Robust Reading Competition](https://rrc.cvc.uab.es/); [Baek et al.](https://arxiv.org/abs/1904.01906))

The target failure cases should be explicit: missed or merged small words in clutter; wrong reading under rotation and perspective; curved text damaged by rectangular crops; blur/low pixel height; occlusion and low contrast; and Czech diacritics or mixed Czech–English strings. Break results down by language, scene, text pixel height and capture condition. Public labels rarely provide a complete taxonomy for blur type, illumination or severity, so annotate a small condition tag set yourself rather than implying a benchmark provides it. Most candidates are still-image datasets, not tests of camera motion, frame stability or sustained mobile latency. ([ICDAR 2015](https://rrc.cvc.uab.es/?ch=4); [Total-Text](https://github.com/cs-chan/Total-Text-Dataset); [TextZoom](https://arxiv.org/abs/2005.03341))

## Add a sealed Czech–English set and protect its provenance

No established public Czech real-scene benchmark with comprehensive word-level ground truth was identified in the reviewed primary sources. Build a permissioned private panel of roughly **1,000–2,000 new images** across Czech and English signs, menus, packaging, posters and wayfinding, including genuine diacritics, mixed-language names, small text, perspective, blur, low light and occlusion. This is a proposed evaluation design, not an existing dataset. Reserve about 15% for development and seal the rest for testing; split by location, capture session and source rather than adjacent images, and deduplicate with image/text checks. Obtain permissions appropriate to capture and evaluation, and restrict image/label distribution to authorized evaluators unless explicit rights allow publication. A reproducibility package can publish IDs or hashes, annotation schema, scripts and aggregate results without republishing images. ([PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR); [RapidOCR model licensing notes](https://github.com/RapidAI/RapidOCR/blob/main/MODEL_LICENSES.md))

**Minimal recommendation:** run ICDAR 2015, TextOCR, Total-Text and TextZoom, then add the private Czech–English panel; omit the optional script-specific sets unless they match intended users. For each, retain the official split, report detection F-score, fixed-crop CER/normalized edit distance and end-to-end word F-score, with Czech and English strata and latency/memory on a fixed machine. Benchmark terms are dataset-specific: registration or a downloadable mirror is not permission to redistribute or use commercially, and permissive software licenses do not grant image rights. Verify terms for the precise release and use case before operationalizing the suite. The private panel is what turns benchmark results into evidence for the intended camera conditions—and prevents a runtime-parity result from being mistaken for proof that one model family reads Czech scenes better.

## Conclusion

Treat runtime choice and OCR quality as separate decisions: matching PaddleOCR-derived weights can establish whether RapidOCR’s deployment path preserves behavior and improves operational fit, while independent checkpoints are needed for model-quality claims. The public shortlist diagnoses complementary weaknesses; the Czech–English held-out captures determine whether those weaknesses matter in the real application.
