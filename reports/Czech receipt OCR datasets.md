# Find the right receipt OCR test

**No publicly downloadable Czech účtenka/faktura image-plus-transcript dataset was verified in this research pass.** The local test ground now includes **200 CORD-v2 Indonesian receipts**, **4,373 TextZoom low/high-resolution pairs** of real-scene word crops, a **626-image corrected SROIE mirror subset** with OCR box/transcript and key-field labels, and **350 XFUND validation forms** across seven languages. The SROIE copy is a public participant mirror, not the full 1,000-image official challenge; its repository MIT code license does not clearly license the receipt scans, so it is retained for this nonprofit research workspace only and not redistributed. TextZoom is scene text rather than receipts and has no clear dataset-specific redistribution license. XFUND is stated CC BY-NC-SA 4.0 (noncommercial, attribution, share-alike) but is neither Czech nor receipt imagery. None of these datasets measures Czech receipt accuracy. The next decision-grade test should be a small, permissioned Czech receipt panel. DocILE remains access-controlled and provides KIE/LIR labels with precomputed OCR rather than complete OCR ground truth.

## Czech dataset searches found software, not a verified corpus

The searches recorded in the notes returned no results for “czech receipt” or “uctenka” in the Hugging Face dataset API, and no dataset repositories for the queried Czech receipt/invoice phrases on GitHub. The Czech-related projects that did surface—`uctenka` and `uctenkomat`—are receipt-processing applications; their metadata does not document a released image corpus, paired transcripts, corpus size, or dataset terms. The repository MIT license for `uctenkomat` licenses software, not user receipt photographs, and the other project lists no repository license. This is a **bounded negative finding**, not proof that no private, gated, academic, or differently named Czech corpus exists; broader Czech scholarly and institution-level catalog searches remain open. ([Hugging Face search: czech receipt](https://huggingface.co/api/datasets?search=czech%20receipt); [Hugging Face search: uctenka](https://huggingface.co/api/datasets?search=uctenka); [GitHub search: Czech receipt OCR dataset](https://api.github.com/search/repositories?q=czech+receipt+OCR+dataset); [uctenkomat](https://github.com/kubiq/uctenkomat); [uctenka](https://github.com/aykoooo/uctenka))

The practical threshold for calling a candidate a dataset is evidence of **real receipt or invoice images, paired text or structured labels, a working access route, and terms covering those data**. None of the Czech-specific records checked satisfies that threshold. International datasets should not be relabeled “Czech” unless Czech language and provenance are actually documented. ([Hugging Face Czech invoice search](https://huggingface.co/api/datasets?search=invoice%20Czech); [GitHub Czech invoice search](https://api.github.com/search/repositories?q=Czech+invoice+dataset+OCR+images))

## The local 200-image CORD copy is ready for proxy testing

CORD contains Indonesian receipts and provides image-level OCR supervision, including text and quadrilateral localization as well as structured receipt parsing. The project describes 11,000-plus collected receipts but releases a 1,000-image annotated sample across 800/100/100 train/dev/test; its public project terms state CC BY 4.0. The local repository keeps only the **100 validation and 100 test images** and their `ground_truth` strings—not the full release or training set. Direct inspection found 200 JPEGs (30,304,679 bytes total), 200 corresponding label rows, and no missing images. The local copy and downloader are documented at `$DATASETS_ROOT/source/cord-v2/DATASET_INFO.md` and `scripts/download_cord.py`. ([CORD project and annotation details](https://github.com/clovaai/cord); [CORD v2 on Hugging Face](https://huggingface.co/datasets/naver-clova-ix/cord-v2); [CC BY 4.0 license](https://github.com/clovaai/cord/blob/master/LICENSE-CC-BY))

This subset is immediately useful for **end-to-end smoke tests, output/schema checks, and paired PaddleOCR/RapidOCR runs**, not a representative quality estimate: it is Indonesian, and both its language and receipt conventions differ from Czech. The project README correctly frames its scores as pipeline smoke-test/cross-system comparisons. The upstream repository’s CC BY 4.0 statement requires attribution, but underlying image rights still deserve separate review before redistribution; the project’s own local note says not to redistribute the copy without checking. ([Local OCR README](../README-ocr.md); local CORD note at `$DATASETS_ROOT/source/cord-v2/DATASET_INFO.md`; [CORD dataset terms](https://github.com/clovaai/cord/blob/master/LICENSE-CC-BY); [Creative Commons BY 4.0](https://creativecommons.org/licenses/by/4.0/))

The TextZoom test LMDBs and exported crops are in `$DATASETS_ROOT/source/textzoom/test/` and `$DATASETS_ROOT/derived/textzoom/test_export/`. With case, punctuation/symbols, and decomposable Latin diacritics ignored, all 4,373 low-resolution crops scored PaddleOCR CER/WER 0.389/0.500 (median 0.078 s/image); RapidOCR 0.442/0.522 (0.083 s/image). CORD's 200-image held-out subset scored PaddleOCR 0.190/0.282 (1.20 s/image); RapidOCR 0.169/0.265 (1.89 s/image). The first 100 SROIE mirror images scored PaddleOCR 0.056/0.150 (2.84 s/image); RapidOCR 0.052/0.140 (3.87 s/image). Strict and case-insensitive scores are retained alongside ASCII-fold scores in `runs/ascii-fold/summary.json`. Both comparisons used PP-OCRv6-small, CPU ONNX Runtime, and orientation disabled. These are local diagnostics, not official challenge submissions; RapidOCR uses converted model artifacts, so differences cannot be attributed only to package code. None is Czech. ([TextZoom](https://github.com/WenjiaWang0312/TextZoom); [CORD](https://github.com/clovaai/cord); [local harness README](../README-ocr.md))

## CORD, SROIE and DocILE answer different benchmark questions

**CORD is the clearest low-friction receipt OCR benchmark in this review.** Its images and text-level labels support recognition and receipt parsing, its source explicitly states CC BY 4.0, and the project links a small v0 download as well as the 1,000-row v2 Hugging Face release. That license/access clarity makes CORD the best external proxy for a quick repeatable run, subject to attribution and the image-rights caveat. ([CORD repository](https://github.com/clovaai/cord); [CORD v2 card](https://huggingface.co/datasets/naver-clova-ix/cord-v2))

**SROIE is a strong task match but a weaker rights proposition.** The official challenge describes 1,000 scanned receipts. The participant mirror includes a corrected 626 image/box/key subset. Its MIT license covers repository software; image rights remain unverified, so the images are kept local and not redistributed. On the first 100 mirror records, ASCII-fold PaddleOCR CER/WER were 0.056/0.150 (median 2.84 s/image); RapidOCR 0.052/0.140 (3.87 s/image). Strict-case and case-insensitive metrics are retained separately. This is not an official challenge score, and the mirror does not preserve the official split mapping. ([ICDAR SROIE challenge](https://rrc.cvc.uab.es/?ch=13&com=introduction); [SROIE participant repository](https://github.com/zzzDavid/ICDAR-2019-SROIE); [best/median/worst examples](SROIE%20example%20comparisons.md))

**DocILE is for business-document understanding, not a drop-in OCR transcript benchmark.** It covers real business documents and invoice-like field/line-item extraction at scale, offers precomputed DocTR OCR words, and requires a Dataset Access Request form and token-based downloads. Its KILE/LIR labels and OCR predictions should not be treated as complete human ground-truth page transcripts; request and read current access terms before using it. EPHOIE (Chinese exam-paper OCR) requires an institutional research application; neither it nor the locally downloaded XFUND multilingual forms is a receipt or Czech substitute. RVL-CDIP is classification-only and has no OCR transcription labels. ([DocILE site/access](https://docile.rossum.ai/); [DocILE repo](https://github.com/rossumai/docile); [EPHOIE access](https://github.com/HCIILAB/EPHOIE); [XFUND release/license](https://github.com/doc-analysis/XFUND); [RVL-CDIP](https://www.cs.cmu.edu/~harley/rvl-cdip))

## Build a small sealed Czech panel as the next test

The next meaningful test set is **new, permissioned Czech receipt images with manually checked transcripts**, not a larger count of unrelated foreign receipts. Start with roughly 100–200 receipts as a pilot, then expand toward 500–1,000 if annotation quality and capture diversity justify it. This is a proposed engineering design rather than an existing public corpus. Capture both printed receipts and invoices only if both are in scope; include varied retailers, thermal-paper fading, phone angles, blur, low light, folds, glare, small print, long item descriptions, totals, dates, VAT identifiers, and Czech diacritics. Preserve the original image, full text transcript, line/word boxes where feasible, structured key fields, provenance/consent record, and a split grouped by store/source and capture session to limit leakage.

For immediate model comparison, use CORD as the receipt smoke test and SROIE as the scanned-receipt English benchmark proxy, with its terms caveat. Use TextZoom for crop-level low-resolution scene OCR. A Czech pilot remains necessary for local quality decisions. The evaluation harness reports CER/WER as normalized edit counts; these error rates can exceed 1.0 when inserted text is long. See [`reports/SROIE example comparisons.md`](SROIE%20example%20comparisons.md) for full best, median, and worst cases with ground truth, both OCR outputs, metrics, and image references. ([Local OCR README](../README-ocr.md); [DocILE](https://docile.rossum.ai/))

## Conclusion

The dataset gap is specifically a **Czech labeled-image gap**, not a lack of international receipt OCR data. CORD already provides a compact, reproducible proxy for exercising the pipeline, while SROIE and DocILE can broaden task coverage only within their distinct annotation and access limits. A small permissioned Czech pilot would create more decision-relevant evidence than treating non-Czech benchmark scores as local performance; expand it only after the first annotation round shows what kinds of receipts and failure cases the project actually needs to cover.
