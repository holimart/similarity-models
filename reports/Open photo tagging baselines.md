# Choose and measure open photo taggers

Frozen local models provide useful photo-tagging baselines without fine-tuning, but no single public dataset measures the full value of stock-style tags. COCO 2017 validation images and annotations are downloaded under `/mnt/sportsmarket/datasets/coco2017`, configured with `COCO_ROOT` in the ignored project `.env`, and model packages are installed via `uv`. On the same first 50 validation images, **RAM++ scored 0.852 macro mAP**, close to COCO-supervised Faster R-CNN's 0.888 and above SigLIP 2 at 0.756 and CLIP at 0.622. CLIP was fastest on CPU; RAM++ is purpose-built for tags but considerably slower. These preliminary results do not generalize to the full COCO split or measure stock-search quality. Add Open Images' explicitly verified positive/negative labels and a human-reviewed target-domain set before making production claims.

## Public datasets measure different slices of tagging

**Open Images V7 is the strongest broad object-label benchmark in this set.** It reports about 9 million images and 20,638 image-level classes, with human-verified labels across the full validation and test splits. A verified positive means present and a verified negative means absent; unlabeled class/image pairs are unknown, not negative. Its scale and verified negatives support masked multi-label evaluation, but its ontology remains object-heavy and labels are incomplete. Limit evaluation to classes with meaningful support and preserve the positive/negative/unknown distinction. The official site documents selective downloads and per-image source/license metadata, while requiring users to verify individual image rights ([V7 facts and figures](https://storage.googleapis.com/openimages/web/factsfigures_v7.html), [download and formats](https://storage.googleapis.com/openimages/web/download_v7.html)).

**COCO is the most practical first engineering benchmark**, especially its 5,000-image 2017 validation split and instance annotations. Deduplicating each image's non-crowd object categories creates an 80-category multi-label target; this evaluates image-level recognition, not detection localization. Captions are useful for a separate language task, but describe salient content rather than provide exhaustive tags. The official downloads and API are documented at [COCO](https://cocodataset.org/#download) and [cocoapi](https://github.com/cocodataset/cocoapi). The implemented loader excludes crowd annotations from image-level presence. COCO image access does not itself grant blanket rights to redistribute the underlying photographs; check current [terms](https://cocodataset.org/#termsofuse) and image-level provenance.

**NUS-WIDE and PASCAL VOC add useful but narrower comparisons.** NUS-WIDE has 269,648 Flickr images, 81 manually annotated concepts, and user tags, making it relevant to fixed-vocabulary multi-label work and historical comparisons, but not a complete tag inventory. Its official download endpoint and current image terms were not verified in the research notes; treat third-party mirrors cautiously and record image retrieval failures ([original paper](https://doi.org/10.1109/CIVR.2009.5069152), [project page](https://lms.comp.nus.edu.sg/wp-content/uploads/2019/research/nuswide/NUS-WIDE.html)). VOC's fixed 20 object classes make it a compact sanity check, but too narrow for broad stock-photo vocabulary ([VOC2012](http://host.robots.ox.ac.uk/pascal/VOC/voc2012/index.html)). Flickr30k's five human-written captions per image and COCO captions support caption-semantic checks, not exhaustive tag recall ([Flickr30k](https://shannon.cs.illinois.edu/DenotationGraph/data/index.html), [COCO captions](https://cocodataset.org/#captions-2015)). Across these datasets, object presence does not measure lighting, composition, intended use, mood, or buyer-query relevance.

## Local frozen models trade vocabulary flexibility for evidence type

The current code deliberately compares models with different strengths, not interchangeable architectures. **CLIP ViT-B/32** embeds each COCO category prompt (`a photo of {category}`) and each image, normalizes both, then returns cosine similarities against all 80 labels. It can rank a supplied vocabulary without training and runs on CPU or CUDA through PyTorch/OpenCLIP. Similarities are ranking scores, not calibrated probabilities; adding or changing candidate labels can affect interpretation. The OpenAI CLIP model card frames deployment as out of scope and calls for thorough in-domain testing, so its downloadable availability and MIT code license should not be treated as general deployment clearance ([OpenAI CLIP repository and model card](https://github.com/openai/CLIP), [OpenCLIP](https://github.com/mlfoundations/open_clip)).

**TorchVision Faster R-CNN ResNet-50 FPN** detects localized objects using COCO-pretrained weights. The implementation maps detector category names to COCO's 80 labels and collapses all detections of a category to the maximum confidence for that image. It therefore supplies object-localization-derived evidence and a score that behaves differently from CLIP's cosine similarity. It is a closed-set COCO detector, not a general natural-language tagger; it cannot score arbitrary concepts, and its detection scores are not automatically calibrated. TorchVision's catalog provides model/weight documentation, while warning that exact pretrained-weight terms can differ from the library code license ([TorchVision models and weights](https://docs.pytorch.org/vision/stable/models.html), [Faster R-CNN API](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.detection.fasterrcnn_resnet50_fpn.html)).

| Baseline | Output in this implementation | Best first use | Important qualification |
|---|---|---|---|
| CLIP ViT-B/32, OpenAI checkpoint | Cosine similarity per COCO category prompt | Frozen zero-shot ranking over a chosen vocabulary | Prompt and candidate-set dependent; not a probability; model card has restrictive deployment guidance |
| Faster R-CNN ResNet-50 FPN, TorchVision COCO weights | Maximum box confidence per COCO category | Object detection-derived object presence | Fixed detector ontology; COCO-supervised, not zero-shot |
| SigLIP 2 Base, Google | Sigmoid image/text score per COCO category prompt | Newer promptable image/text baseline | 0.4B parameters; CPU inference is relatively slow; score threshold needs calibration |
| RAM++, Swin-Large | Sigmoid score per RAM tag, mapped to COCO labels by synonyms | Direct broad-vocabulary photo tagging | CPU-heavy; some COCO labels need synonym mapping |

Other practical local frozen options include **SigLIP base** for independent image/text label scores via Transformers, **OpenCLIP** checkpoints for a broad range of model recipes, and caption-focused **BLIP-base**, **GIT-base-coco**, or **Florence-2-base-ft**. These can all run locally with PyTorch-based stacks; CPU execution is feasible for many checkpoints but does not guarantee acceptable throughput. SigLIP's sigmoid pair scores naturally fit co-occurring labels better than a softmax across CLIP candidates, yet still need validation and threshold calibration. Captioners generate sentences rather than controlled multi-label decisions, so evaluate caption quality separately and audit unsupported claims. Check the exact checkpoint license and terms, not just the Python package license ([SigLIP model guide](https://huggingface.co/docs/transformers/model_doc/siglip), [SigLIP checkpoint](https://huggingface.co/google/siglip-base-patch16-224), [BLIP](https://huggingface.co/Salesforce/blip-image-captioning-base), [Florence-2](https://huggingface.co/microsoft/Florence-2-base-ft)). TorchVision ImageNet classifiers such as MobileNet V3 or EfficientNet-B0 are smaller CPU-oriented alternatives, but their single-label ImageNet heads are not exhaustive multi-object taggers ([TorchVision catalog](https://docs.pytorch.org/vision/stable/models.html)).

## The repository has a measured 50-image CPU smoke comparison

[`image_tagger/benchmark.py`](../image_tagger/benchmark.py) loads COCO instance JSON, sorts image IDs, skips absent image files, constructs an image-level multi-hot vector, supports four model backends, times per-image prediction, computes metrics, and optionally writes JSON. Models are invoked separately in the compatible uv environments documented in [`image_tagger/README.md`](../image_tagger/README.md). The implementation uses `FasterRCNN_ResNet50_FPN_Weights.DEFAULT`, which is convenient but can alias a changing version; pin an explicit weight enum and record package/model revisions for reproducibility. It reports mean and median timing but has no warmup or p95 latency. The reported `precision@5` always selects five labels even when scores are weak, so interpret it as top-five annotation agreement, not a thresholded emitted-tag precision.

The metric set is a useful first pass: macro mAP from continuous scores; macro and micro precision, recall, and F1 at a declared threshold; precision@5; mean/median seconds per image; throughput; and peak CUDA allocated memory when available. The script uses the same numeric threshold (default 0.25) for **unlike score scales**—CLIP cosine similarity and detector confidence—so thresholded comparisons are not intrinsically fair. Keep ranking mAP as the principal threshold-free comparison, report each model's threshold operating point as a separate diagnostic, and choose thresholds on a distinct calibration set if deployment precision/recall matters. The custom AP implementation does not specify a benchmark evaluator convention and sorts ties by input order; use a standard implementation and state its convention for publication. The current output omits per-class AP, p95 latency, model load/cold-start time, and confidence intervals.

The working setup used `uv` and CPU wheels: Python 3.10.12, PyTorch 2.14.0+cpu, TorchVision 0.29.0+cpu, OpenCLIP 3.3.0 and Transformers 5.17.0 for CLIP/SigLIP 2; RAM++ uses Transformers 4.51.3, timm 0.4.12, SciPy, and fairscale due to upstream compatibility. RAM++ source and checkpoint are cached under `/mnt/sportsmarket/model-cache`; `.env` provides `RAM_REPO`, `RAM_CHECKPOINT`, `HF_HOME`, and `TORCH_HOME`. COCO archives came from the official host over HTTP because its HTTPS endpoint failed TLS hostname verification in this environment; archive CRC checks passed before extraction. Dataset root is `/mnt/sportsmarket/datasets/coco2017`.

The first 50 sorted validation images were evaluated batch-1 on CPU at threshold 0.25. That shared numeric threshold is applied to unlike scores—CLIP cosine similarity, SigLIP sigmoid scores, RAM tag scores, and detector confidence—so threshold F1 is not a fair direct comparison. Macro mAP uses raw ranks; precision@5 is also rank-based. Fifty images provide weak coverage of rare classes. RAM++ outputs are mapped to COCO categories with synonyms (e.g. `sofa`→`couch` and `fridge`→`refrigerator`), which adds ambiguity for a few concepts. Raw results: [CLIP](../image_tagger/results/coco-val2017-clip-cpu-50.json), [Faster R-CNN](../image_tagger/results/coco-val2017-fasterrcnn-cpu-50.json), [SigLIP 2](../image_tagger/results/coco-val2017-siglip2-cpu-50.json), [RAM++](../image_tagger/results/coco-val2017-ram-plus-cpu-50.json).

| Model | Macro mAP | Precision@5 | Mean seconds/image | Images/second |
|---|---:|---:|---:|---:|
| CLIP ViT-B/32, OpenAI weights | 0.622 | 0.340 | 0.171 | 5.86 |
| Faster R-CNN ResNet-50 FPN, COCO weights | 0.888 | 0.524 | 6.182 | 0.162 |
| SigLIP 2 Base | 0.756 | 0.428 | 2.029 | 0.493 |
| RAM++ Swin-Large | 0.852 | 0.504 | 12.952 | 0.077 |

These are smoke-test observations, not official benchmark scores. Faster R-CNN is COCO-supervised and closed-vocabulary; CLIP and SigLIP 2 score supplied labels; RAM++ emits from its broad learned tag list. The host has no CUDA device, so GPU performance has not been benchmarked.

Run from the repository root:

```bash
# Dedicated uv environment; use the appropriate PyTorch selector command
# instead of the CPU index on a CUDA-enabled host.
uv venv --python /usr/bin/python3 .venv-image-tagging
uv pip install --python .venv-image-tagging/bin/python torch torchvision \
  --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv-image-tagging/bin/python open_clip_torch transformers

uv venv --python /usr/bin/python3 .venv-tagging-advanced
uv pip install --python .venv-tagging-advanced/bin/python torch torchvision \
  --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv-tagging-advanced/bin/python \
  transformers==4.51.3 timm==0.4.12 scipy fairscale

# COCO is already downloaded at COCO_ROOT from the repository .env.
.venv-image-tagging/bin/python image_tagger/benchmark.py \
  --model siglip2 --limit 50 --device cpu \
  --output image_tagger/results/coco-val2017-siglip2-cpu-50.json
.venv-tagging-advanced/bin/python image_tagger/benchmark.py \
  --model ram_plus --limit 50 --device cpu \
  --output image_tagger/results/coco-val2017-ram-plus-cpu-50.json
```

Omit `--limit 50` to evaluate all available validation images. Use `--device cpu` to force CPU; the default automatically selects CUDA when available. Timings include image loading and preprocessing and are not portable hardware guarantees. Model weights are cached locally after first use.

## Metrics need partial-label and target-domain discipline

For COCO's derived category-presence task, macro mAP over per-class average precision measures ranking across thresholds and gives each evaluable class equal weight; micro metrics pool decisions and are more influenced by common classes. Precision, recall, and F1 at a fixed threshold describe one operating point; precision@k measures how often the top-ranked tags match recorded labels, but says nothing about relevant tags ranked below k. Report per-class support and scores alongside macro/micro summaries. For Open Images, compute metrics only over explicitly verified positive/negative pairs, masking unknowns; never silently count every unannotated class as a negative. Open Images' official challenge metric is detection-specific and is not directly interchangeable with image-level classification mAP ([Open Images evaluation](https://storage.googleapis.com/openimages/web/evaluation.html), [scikit-learn AP documentation](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)).

Keep test IDs, candidate labels, prompt strings, transforms, checkpoint revisions, package versions, device, precision, batch size, and failure/exclusion policy fixed and recorded. Do not tune prompts or thresholds on the final test split. For runtime, report cold model load separately from warmed inference, end-to-end latency including image decode and preprocessing, batch-1 median and p95, throughput, peak host RAM/VRAM, and error rate under identical hardware and image conditions. Published parameter counts and FLOPs are not local latency measurements. For captioning, report caption metrics such as CIDEr-D separately from tag metrics and add human review for factuality; lexical overlap does not certify image-grounded truth ([CIDEr](https://arxiv.org/abs/1411.5726), [caption object hallucination](https://arxiv.org/abs/1809.02156)).

Most importantly, benchmark agreement is not stock-search quality. COCO and ImageNet primarily reward recognizable object categories; useful metadata can include scene, activity, style, composition, and query intent, while captions can omit valid details and models can make unsupported claims. Build a small, stratified, human-reviewed sample of the intended photo domain. Rate emitted tags as supported, unsupported, ambiguous, or wrong granularity, capture important omissions independently, and separately judge retrieval for realistic search queries. This measures both truthfulness and usefulness rather than treating an incomplete label list as complete ground truth ([COCO dataset paper](https://arxiv.org/abs/1405.0312), [Getty contributor guidance](https://www.gettyimages.com/workwithus)).

## Next steps turn the smoke test into a defensible comparison

The 50-image smoke comparison is now run; next pin explicit model weights and dependency versions, decide and document the crowd-annotation policy, and evaluate the complete 5,000-image validation set using a standard AP implementation. Add a calibration split or separate threshold set rather than selecting thresholds on the reported test results. Preserve per-class results and compare ranking metrics separately from model-specific confidence operating points.

Next, add an Open Images V7 adapter that retains verified positive, verified negative, and unknown states, selects a manageable class/image subset, and preserves per-image license/source metadata. COCO offers the quickest integrated starter path; Open Images is the better next step for broader verified image-level tagging. Treat NUS-WIDE as an optional historical comparison only after validating the release, mirror, and rights. Finally, collect human judgments on representative target-domain images and queries, then compare quality, runtime, memory, and retrieval relevance together. This progression keeps a useful distinction intact: a model can be fast and competent at familiar objects while still failing to produce complete, accurate, or commercially useful photo metadata.
