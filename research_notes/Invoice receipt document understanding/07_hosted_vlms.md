# Hosted multimodal LLM APIs for invoice and receipt extraction

## Current API options, extraction constraints, and fit

### Takeaway

Hosted vision-language APIs offer flexible extraction from scans/photos without building an OCR/layout stack, but a schema-conforming response is not evidence that extracted values are correct. For predictable high-volume invoice pipelines, compare end-to-end extraction against a document-specific OCR/API and your own labeled set; multimodal LLMs are especially attractive for variable layouts, semantic interpretation, and exception handling.

### Cited Findings

- **OpenAI GPT-4.1 / GPT-4o.** Standard API list rates are GPT-4.1: $2/M input and $8/M output tokens; GPT-4o: $2.50/M input and $10/M output. GPT-4.1-mini is $0.40/$1.60, and GPT-4o-mini $0.15/$0.60. Batch rates are discounted (e.g., GPT-4.1 $1/$4; GPT-4o $1.25/$5). Pricing page accessed 2026-09-26. — [OpenAI API pricing](https://developers.openai.com/api/docs/pricing/)
- OpenAI vision pricing is via billable image tokens and varies by model, image dimensions, detail, and preprocessing. GPT-4o/GPT-4.1 use a base-plus-tiles method: low detail is 85 input tokens per image; high/auto scales to fit 2048×2048 then may shrink shortest edge to 768px and bills 85 plus 170 tokens per 512px tile. Thus there is no universal fixed per-image price. — [OpenAI images and vision](https://developers.openai.com/api/docs/guides/images-vision)
- OpenAI vision supports image URLs, base64/data URLs, and file IDs; current docs list up to 1,500 images/request and 512 MB payload, though model context/token limits also bind. The docs recommend original/high fidelity for small text/OCR when supported; known limitations include small/rotated text and inaccurate visual interpretation. — [OpenAI images and vision](https://developers.openai.com/api/docs/guides/images-vision)
- OpenAI Structured Outputs support strict JSON Schema response formatting and function/tool calling, with model/schema eligibility restrictions; documentation describes support in newer models beginning with GPT-4o. For simple invoice output, response JSON Schema is more direct than function calling. Check supported schema subset and model list for the chosen endpoint. — [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- **Anthropic Claude.** API list rates: Sonnet 5 $2/M input and $10/M output; Sonnet 4.6 $3/$15; Haiku 4.5 $1/$5; Opus 5.5 $4/$20. Batch processing halves token charges. Use the currently listed rates rather than older model-rate summaries; pricing page reports Sonnet 5 introductory $2/$10 became standard and the scheduled September 2026 increase was cancelled. — [Anthropic model pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Claude image input is billed as visual tokens based on 28×28 patches after provider resizing. For standard resolution, a 1000×1000 image is 1,296 tokens; a high-resolution-capable model can retain more detail and use more tokens. Standard tier caps around 1,568 visual tokens; high-resolution Claude 4.7+ tier up to 4,784. Visual tokens incur normal model input rates. — [Claude vision: resolution and token cost](https://platform.claude.com/docs/en/build-with-claude/vision#resolution-and-token-cost)
- Claude API accepts base64, URL, or Files API images; supports up to 100 images/request for 200k-context models (600 for other models), with per-image, aggregate request-size, dimension, and platform caveats. Anthropic says low-quality, rotated, or very small images can be misread and instructs users to verify outputs. — [Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision)
- Claude supports schema-constrained JSON output and strict tool-use schemas. Structured outputs are generally available on the documented supported model set; JSON Schema is a supported subset, so schema constraints may need transformation/removal. Tool use adds input token overhead beyond tool schema tokens. — [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs); [Anthropic tool pricing](https://platform.claude.com/docs/en/about-claude/pricing#tool-use-pricing)
- **Google Gemini on Vertex AI / Agent Platform.** The Google Cloud pricing page currently lists Gemini 3.8 Flash (introductory through Dec. 31, 2026) at $0.75/M input and $3.75/M output globally, with images included in the input token rate. Gemini 3.1 Pro Preview is $2/M input (up to 200k context) and $12/M text output. Exact Google AI Studio/Gemini API rates may differ from Vertex rates; do not transfer these prices between billing products without checking the relevant current rate card. — [Google Cloud generative AI pricing](https://cloud.google.com/vertex-ai/generative-ai/pricing)
- Vertex pricing presents Gemini Flash image and text as a shared token-priced input class, but actual image token use varies with the image/model and should be read from usage metadata or estimated from current model documentation. Its Live API has an explicitly stated 258 tokens per image, which is a Live API-specific conversion and must not be assumed for standard generateContent invoice extraction. — [Google Cloud generative AI pricing](https://cloud.google.com/vertex-ai/generative-ai/pricing)
- Gemini provides document understanding, image understanding, structured output, and function calling; JSON Schema constraints and combinations with tools depend on model/API mode. Confirm feature compatibility for selected model and SDK version. — [Gemini document understanding](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/document-understanding); [Gemini structured output](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/control-generated-output); [Gemini function calling](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/function-calling)
- **Mistral.** The current Mistral-hosted OCR 4.1 service is $4 per 1,000 pages, with $5/1,000 annotated pages. It returns paragraph-level bounding boxes, structural block labels, and block-level confidence scores. This is specialized OCR/document parsing, not an end-to-end guarantee of normalized invoice semantics or accounting validation. — [Mistral OCR 4.1 model card](https://docs.mistral.ai/models/ocr-4-1/); [Mistral inference pricing](https://docs.mistral.ai/inference/pricing/)
- General Mistral-hosted multimodal model list prices include Mistral Small 4 at $0.15/M input, $0.60/M output; Ministral 3 8B $0.15/$0.15; Mistral Large 3 $0.50/$1.50; Medium 3.5 $1.50/$7.50. The listed pricing page does not explain a uniform per-image token conversion; use API-reported usage and validate image inclusion for the exact model rather than assuming a page fee. — [Mistral inference pricing](https://docs.mistral.ai/inference/pricing/); [Mistral models overview](https://docs.mistral.ai/getting-started/models/models_overview/)
- Mistral positions OCR 4.1 as the dedicated document route and its general models as multimodal. No fully accessible official structured-output capability page was found in this research pass; validate JSON-schema enforcement/tool compatibility on the model/API endpoint directly before designating it equivalent to OpenAI/Anthropic constrained decoding. — [Mistral OCR 4.1](https://docs.mistral.ai/models/ocr-4-1/); [Mistral models overview](https://docs.mistral.ai/getting-started/models/models_overview/)
- **Reliability evidence.** Vendor API documentation explains image limits and acknowledged failure modes, but is not a controlled invoice/receipt benchmark. No apples-to-apples, independently reproducible field-level invoice extraction evaluation for the exact current hosted models and pricing snapshot was established from the official documents reviewed. General document benchmarks such as DocVQA measure related document question answering, not exact invoice-field accuracy, total correctness, or production abstention rate. — [DocVQA dataset/paper](https://arxiv.org/abs/2007.00398)

### Inferences

- Likely best fit: GPT-4.1/4o and Claude Sonnet for flexible, schema-directed extraction where layout varies and semantic interpretation matters; Gemini Flash for economical broad multimodal workloads where measured accuracy passes; Mistral OCR 4.1 where layout-aware OCR, reading order/blocks, bounding boxes, and confidence are needed or where a dedicated OCR pass can precede a reasoning model. These are product-fit inferences, not a model leaderboard.
- Likely worst fit for any general VLM alone: workflows requiring guaranteed correct arithmetic, tax/legal compliance, exact line-item reconciliation, field provenance, or near-zero error without review. Constrained decoding guarantees structure, not truth; enforce cross-field arithmetic, currency/date/business rules, confidence thresholds, and human exception review.
- A hybrid pipeline (OCR/layout extraction followed by selective VLM normalization or exception resolution) can reduce image uncertainty and make fields auditable, but increases stages and integration overhead. Benchmark both that and direct-image prompting on actual receipts, low-quality photos, multi-page invoices, languages, and supplier templates.
- Model selection by “cost per image” is misleading when providers expose token billing: page dimensions, number of crops/tiles/patches, output length, prompt size, retries, batch discounts, and page count per document all change spend.

### Gaps

- No public independent benchmark was located comparing current model versions on the same invoice/receipt corpus with exact field-level metrics (header, totals, tax, line items, currency, dates), OCR quality, latency, and abstention. Build a held-out evaluation from target data.
- Current Gemini pricing and image tokenization vary by product surface and model. Google AI Studio direct pricing/docs endpoints were intermittently inaccessible during research; reported Gemini prices here are Vertex/Agent Platform prices, and image cost for ordinary request mode is deliberately not asserted as a fixed token count.
- Mistral structured-output/tool-mode support and schema restrictions need endpoint-specific confirmation; general Mistral multimodal image token billing rules likewise were not confirmed from a primary accessible documentation source in this research pass.

## Representative cost per 1,000 and 100,000 pages

### Takeaway

Under a transparent one-image/one-page baseline, variable input image charges matter but generated output and prompt tokens also contribute. Specialized Mistral OCR has a clear $4/1k-page list price; VLM totals below are illustrative token estimates rather than quoted per-page tariffs, with especially material uncertainty for Gemini and actual image preprocessing.

### Cited Findings

- Calculation basis: one single-page invoice image per page; 1,000 text input tokens/page (500-token extraction instructions/context plus approximately 500 tokens of image representation and other input, except that vision image tokens are explicitly substituted in the provider-specific estimates below); 200 output tokens/page; USD, standard on-demand rates, no caching, batch discounts, retries, taxes, storage, network, downstream validation, or OCR preprocessing. Prices and tokenization references are linked above.
- **OpenAI GPT-4o estimate.** Use a representative 1024×1024 image at high detail: 85 base + 4 tiles ×170 = 765 image tokens (image resizes to 768 shortest edge under documented rule). Add 500 textual input tokens and 200 output tokens. At $2.50/M input and $10/M output: `(765+500)*2.50/1M + 200*10/1M = $0.0051625/page`, or **$5.16/1k pages; $516.25/100k**. Image estimate is assumption-sensitive: image geometry and `detail` change tile count.
- **OpenAI GPT-4.1 estimate.** Same assumed token counts at $2/M input and $8/M output: `(765+500)*2/1M + 200*8/1M = $0.00413/page`, or **$4.13/1k; $413/100k**. For high-quality dense invoices consider higher-resolution preprocessing and recalculate image tokens.
- **Anthropic Claude Sonnet 5 estimate.** At 1000×1000 image, documented standard resolution cost is 1,296 visual tokens; with 500 text input and 200 output, at $2/M and $10/M: `(1296+500)*2/1M + 200*10/1M = $0.005592/page`, or **$5.59/1k; $559.20/100k**. Image patches depend on actual dimensions/resizing. Batch would halve token spend under current batch terms.
- **Google Gemini 3.8 Flash Vertex estimate (image token count uncertain).** As a disclosed proxy only, use the Live API documented 258 tokens/image, plus 500 text-input tokens and 200 output tokens; applying Vertex Flash $0.75/M input + $3.75/M output gives `(258+500)*0.75/1M + 200*3.75/1M = $0.0013185/page`, or **$1.32/1k; $131.85/100k**. This is not a reliable standard Vertex image estimate because the 258 token conversion is specifically Live API; standard document/image input may differ. For general Vertex mode use actual `usageMetadata` from representative requests before budgeting.
- **Mistral OCR 4.1 alone:** quoted $4/1,000 pages = **$4/1k; $400/100k** (regular pages; annotated output quoted separately at $5/1,000). It extracts text/layout, not necessarily normalized invoice JSON. If followed by a general LLM, add language-model input/output charges.
- **Mistral OCR 4.1 + illustrative Small 4 normalization:** assume OCR text and prompt total 1,000 input tokens/page, output 200 tokens/page; Mistral Small 4 rates $0.15/M and $0.60/M. LLM portion = `$0.00027/page` = $0.27/1k; total **$4.27/1k; $427/100k**, excluding annotation fee and any extra tokens. Text length can be much higher for itemized invoices.
- **Scale is linear in page count in these simple scenarios:** multiply per-page total by 1,000 or 100,000 respectively; document-level prompts, pages batched in one request, retries, and multi-page context may break that assumption.

### Inferences

- For a single-page typical invoice, inferred costs are on the order of $1–6 per 1,000 pages in the modeled provider-token scenarios, excluding any separate OCR or significant line-item output. Differences at this scale are often smaller than the cost of error handling and manual review.
- Long line-item tables can multiply output tokens substantially; low-res receipts can require larger image detail/crops or retries; the table estimates are therefore baseline rather than upper bounds.
- Mistral's per-page OCR rate is more predictable from page count than token-priced VLMs, but should not be treated as a full normalized extraction price. OCR text length and downstream model charge add variance.

### Gaps

- There is no fixed dollar cost for OpenAI/Claude/Gemini/Mistral general VLM image per page independent of image dimensions/model controls. Measure image usage reported by each API on a representative image sample and recalculate.
- Some Google pricing tables distinguish AI Studio and Vertex/Agent Platform; verify billing product, region, batch eligibility, and current model ID at deployment time.
- Typical output token volume varies substantially by schema (header-only versus 100+ line items); no one assumed 200-token output should substitute for a workload-specific token histogram.

## Operational reliability, structured outputs, and use-case guidance

### Takeaway

Use schemas to make downstream software safer, then independently validate values. The strongest operational evidence available in this review is provider documentation about schema enforcement, image handling, and known limitations—not comparative field accuracy claims.

### Cited Findings

- OpenAI Structured Outputs promises JSON Schema adherence for supported models/schema subset and exposes refusals programmatically; API documentation differentiates response-format schema outputs from function/tool calls. — [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- Anthropic JSON outputs use constrained decoding, and strict tool use validates tool name/input schema; APIs document a restricted JSON Schema subset. These mechanisms reduce formatting/retry errors, not semantic extraction errors. — [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)
- Gemini structured output and function calling are distinct capabilities; structured output is useful for predictable response shape, while function calling is for a model-selected operation. Verify particular mode compatibility and schema subset per model. — [Gemini structured output](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/control-generated-output); [Gemini function calling](https://cloud.google.com/vertex-ai/generative-ai/docs/multimodal/function-calling)
- Mistral OCR 4.1 offers block confidence scores and bounding boxes, potentially supporting review routing and source localization. The confidence score is OCR/block-level evidence and should not be read as calibrated correctness of downstream semantic fields. — [Mistral OCR 4.1](https://docs.mistral.ai/models/ocr-4-1/)
- OpenAI documents risks around small text, rotation, and visual accuracy; Anthropic similarly cautions about low-quality, rotated, and very small images. Such conditions are common in mobile receipts and faxed invoices, strengthening case for quality checks, orientation correction, and escalation. — [OpenAI vision limitations](https://developers.openai.com/api/docs/guides/images-vision#limitations); [Claude vision limitations](https://platform.claude.com/docs/en/build-with-claude/vision#limitations)
- DocVQA is a research dataset/benchmark for document visual question answering and is informative for document comprehension, but a benchmark result does not directly establish invoice field exact-match or total-reconciliation performance. — [DocVQA paper](https://arxiv.org/abs/2007.00398)

### Inferences

- **Best use cases:** (1) heterogeneous supplier invoice/receipt layouts; (2) extracting fields that require context or interpretation, such as invoice vs. credit note classification; (3) rapid prototyping where schema changes frequently; (4) field normalization from OCR text; (5) exception-only second pass over low-confidence or arithmetic-inconsistent docs.
- **Worst use cases:** (1) zero-human-touch payments where a single wrong total/vendor/bank detail causes loss; (2) dense line-item tables without reconciliation; (3) tiny, blurry, rotated, or severely compressed receipts without image enhancement; (4) tasks requiring guaranteed provenance/citations or calibrated confidence unless surrounding pipeline supplies it; (5) broad multi-page batches that exceed image/context/request limits.
- Use nullable/explicit unknown fields rather than prompting a model to guess; request source snippets/coordinates if supported by selected workflow; validate subtotal + tax + discounts = total, currency and date formats, duplicate invoice IDs, and vendor master-data matches in deterministic code.
- Measure field-level exact match, normalized match, numeric tolerance, table row precision/recall and ordering, false-completion rate, abstention quality, latency, and dollar cost. Evaluate separate clean PDFs, scans, phone photos, handwriting, low-light, multilingual docs, and unseen vendors; report critical-field error rates, not just average score.

### Gaps

- Vendor-published examples and API feature guarantees do not quantify production reliability for a given invoice distribution. A private, held-out corpus with gold labels remains necessary.
- API support, model names, pricing, limits, and constrained decoding evolve quickly; re-check linked live documentation and pin dated model IDs before launch.
