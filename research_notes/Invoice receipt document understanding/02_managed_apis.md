# Managed invoice and receipt document-understanding APIs

## What do the main managed platforms extract, and how comparable are their accuracy claims?

### Takeaway
The hyperscalers offer focused pretrained extraction APIs that return OCR plus normalized fields and line items; ABBYY Vantage is a broader low-code intelligent-document-processing platform with configurable skills, review, and workflow integrations. Vendor accuracy statements are not directly comparable: the reviewed primary sources do not publish a shared invoice/receipt benchmark, and ABBYY's “90% accuracy at the start” claim lacks a metric definition and test set on its overview page.

### Cited Findings
- Amazon Textract `AnalyzeExpense` analyzes invoices and receipts synchronously; `StartExpenseAnalysis`/`GetExpenseAnalysis` provide asynchronous processing. Output contains `ExpenseDocuments`, summary fields and line-item groups, with detected values, labels, confidence and geometry. [AWS AnalyzeExpense documentation](https://docs.aws.amazon.com/textract/latest/dg/analyzing-document-expense.html)
- AWS's product pricing page describes Analyze Expense as a pretrained API with OCR included. It gives an Oregon example of $0.01/page for the first million pages in a month and $0.008/page thereafter; actual rates can vary by region. It lists a 100-page/month free-tier allocation for three months for new customers. [AWS Textract pricing](https://aws.amazon.com/textract/pricing/)
- Azure Document Intelligence v4.0 `prebuilt-invoice` extracts invoice-specific data and line items from invoices, utility bills, sales orders, and purchase orders, including customer/vendor data, dates, amounts, and line items. It handles phone images, scans, and digital PDFs. The result includes recognized text, page/table results, and document-specific results; optional key-value-pair extraction is disabled by default in v3.1/v4.0. [Microsoft invoice model](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/invoice?view=doc-intel-4.0.0)
- Azure `prebuilt-receipt` extracts merchant and transaction information, totals and itemized data; v4.0 also adds receipt type, tax details, country/region, and VAT table extraction for general hotel receipts. It supports printed and handwritten receipt input. [Microsoft receipt model](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/receipt?view=doc-intel-4.0.0)
- Google Document AI has dedicated Invoice Parser and Expense Parser (formerly Receipt Parser). Current pricing calls these pretrained processors and bills in counts of up to 10 pages/document; each count costs $0.10 at listed standard pricing, making a single-page document $0.10 and up to ten pages $0.10. [Google Document AI pricing](https://cloud.google.com/document-ai/pricing)
- Google lists generic Form Parser as extracting key-value pairs, checkboxes, tables and generic entities in 200+ languages, but its pricing is $30 per 1,000 pages for the first million and $20 per 1,000 thereafter. This generic processor is not the dedicated Invoice/Expense parser and should not be treated as equivalent in scope or price. [Google processor list](https://cloud.google.com/document-ai/docs/processors-list); [Google pricing](https://cloud.google.com/document-ai/pricing)
- ABBYY Vantage presents a low-code/no-code IDP platform with pretrained skills and user-designed/trained skills, monitoring, human review/continuous learning, and connectors/REST integration into RPA, BPM, ERP, ECM and other systems. ABBYY says skills can work with structured, semi-structured and unstructured documents and advertises “90% accuracy at the start” on the product page; the page does not specify field-level vs document-level accuracy, corpus, language, or conditions, so treat it as a vendor marketing claim rather than a comparable benchmark. [ABBYY Vantage overview](https://www.abbyy.com/vantage/)
- Microsoft invoice docs describe extracted information and confidence-bearing JSON output, but the reviewed primary source does not publish a general numeric accuracy rate. The reviewed AWS and Google sources likewise did not establish a like-for-like published invoice/receipt accuracy percentage. [Microsoft invoice model](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/invoice?view=doc-intel-4.0.0); [AWS AnalyzeExpense documentation](https://docs.aws.amazon.com/textract/latest/dg/analyzing-document-expense.html); [Google processor list](https://cloud.google.com/document-ai/docs/processors-list)

### Inferences
- For a simple API-to-JSON use case, AWS/Azure/Google dedicated processors are the more direct comparison; ABBYY should also be evaluated as an IDP workflow product, including validation, human review, skill configuration and downstream automation—not only extraction fields.
- Compare on a representative, labeled corpus using exact-field match, line-item precision/recall, normalization correctness, confidence calibration, abstention/review rate, and total cost per accepted document. No vendor headline figure substitutes for that exercise.

### Gaps
- No defensible cross-vendor accuracy ranking or equivalent benchmark was found in the reviewed primary sources.
- Detailed ABBYY invoice/receipt field schema and per-field accuracy were not available from the public product overview; obtain skill-specific technical documentation or test access.

## How do language and regional availability affect selection?

### Takeaway
Azure publishes broad language lists for its invoice and receipt models; Google advertises very broad language coverage for general OCR/form parsing, but that does not establish equivalent language coverage for dedicated invoice/expense extraction. AWS AnalyzeExpense's cited API page does not state supported languages, so language and processing-region eligibility need confirmation against current service-specific tables before deployment.

### Cited Findings
- Azure's current invoice model page says invoice extraction supports 27 languages. Its v4.0 receipt support includes a very broad set for thermal receipts and seven named languages for hotel receipts; those are separate receipt categories, not a blanket guarantee for all fields/documents in each language. [Microsoft invoice model](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/invoice?view=doc-intel-4.0.0); [Microsoft receipt model](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/receipt?view=doc-intel-4.0.0); [Microsoft prebuilt language support](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/language-support/prebuilt?view=doc-intel-4.0.0)
- Azure prebuilt invoice language table includes, among others, English, French, German, Spanish, Italian, Portuguese, Japanese, Korean, Arabic, Chinese, and several Central/Eastern European languages. The documented invoice list is version-specific; older API versions support fewer languages. [Microsoft prebuilt language support](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/language-support/prebuilt?view=doc-intel-4.0.0)
- Google Enterprise Document OCR supports more than 200 languages and lists regional processing locations including US, EU, and several named regions. Google warns that processor/version availability varies by region. This is OCR coverage, not proof that Invoice Parser or Expense Parser extracts every schema accurately in all those languages. [Google processor list](https://cloud.google.com/document-ai/docs/processors-list); [Google regions](https://cloud.google.com/document-ai/docs/regions)
- ABBYY describes Vantage cloud instances in Europe, the US, and Australia, and also offers on-premises/private-cloud deployment on Azure. Its public page does not give invoice-skill language-by-language performance coverage. [ABBYY Vantage overview](https://www.abbyy.com/vantage/)
- Textract requests select an AWS Region, and AWS documents synchronous and asynchronous AnalyzeExpense flows; the cited API guide does not itself enumerate expense-language support. [AWS AnalyzeExpense documentation](https://docs.aws.amazon.com/textract/latest/dg/analyzing-document-expense.html)

### Inferences
- Language coverage should be checked at the model-and-field level, not inferred from general OCR language coverage. Vendor language lists do not imply equal accuracy across scripts, handwriting, currencies, or layouts.
- Region names and residency guarantees are distinct. Confirm processor availability, data processing location, storage/retention behavior, and any cross-region operations against the exact SKU and contract.

### Gaps
- Exact current regional endpoint/availability matrix for AWS AnalyzeExpense and Azure's model/SKU was not established from the pages fetched in this research pass.
- ABBYY's invoice and receipt language support matrix was not publicly verified from a primary source.

## What are the pricing, integration patterns, and practical tradeoffs?

### Takeaway
Published consumption pricing spans roughly $0.01/page (AWS at low volume in its US West example) to Google dedicated invoice/expense processing at $0.10 per up-to-10-page document count; these are not strictly comparable units or regions. Azure's pricing endpoint did not expose a clean model-specific price in the retrieved page, and ABBYY directs buyers toward sales/demo rather than publishing a directly comparable per-page tariff.

### Cited Findings
- **AWS:** AnalyzeExpense is $0.01/page for the first million pages/month and $0.008/page beyond that in the Oregon example. A document page is the pricing basis, and OCR is included. The API can take bytes or an S3 object synchronously; async operation uses the Start/Get pattern. [AWS Textract pricing](https://aws.amazon.com/textract/pricing/); [AWS AnalyzeExpense documentation](https://docs.aws.amazon.com/textract/latest/dg/analyzing-document-expense.html)
- **Azure:** The official pricing page is the source of truth, but its retrieved content was not parseable into a reliable prebuilt invoice/receipt unit rate in this research pass. Avoid estimating from third-party price summaries; use the Azure calculator for region, tier, and volume. [Azure Document Intelligence pricing](https://azure.microsoft.com/en-us/pricing/details/ai-document-intelligence/)
- **Google:** Dedicated Invoice Parser and Expense Parser cost $0.10/count, where one count covers up to 10 pages; synchronous requests support no more than 10 pages, while batch requests can process multiple documents up to 200 pages each. Pricing page also notes failed 4xx/5xx requests are not billed. [Google Document AI pricing](https://cloud.google.com/document-ai/pricing)
- **ABBYY:** Vantage is positioned as a broader enterprise platform, with pretrained/marketplace skills, skill design/training, continuous improvement using human-in-the-loop review, connectors, REST API and cloud/private/on-prem deployment choices. ABBYY's public Vantage page does not publish per-page pricing; quote should account for platform/license, transaction volume, skills, deployment and support. [ABBYY Vantage overview](https://www.abbyy.com/vantage/)
- Azure v4.0 supports REST and official C#, Python, Java, and JavaScript SDKs; input includes PDF and common image formats, with paid-tier PDF/TIFF document processing up to 2,000 pages subject to model-specific constraints. [Microsoft invoice model](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/invoice?view=doc-intel-4.0.0)
- Google Document AI supports regional REST endpoints/client libraries and online or batch processing; specialized processors have separate page, request and regional limits. [Google processor list](https://cloud.google.com/document-ai/docs/processors-list); [Google regions](https://cloud.google.com/document-ai/docs/regions)
- ABBYY offers REST API and prebuilt connectors for automation platforms and enterprise systems; Vantage deployment can be ABBYY cloud (Europe/US/Australia) or customer-controlled on-prem/private cloud on Azure according to its product overview. [ABBYY Vantage overview](https://www.abbyy.com/vantage/)

### Inferences
- Estimate total cost rather than API price alone: include pages per document, retry rates, preprocessing, workflow/orchestration, storage, review labor, currency/normalization, and custom-skill or subscription charges.
- AWS is attractive when an AWS-native workflow and page-based usage model matter; Azure has a convenient distinct invoice/receipt model pair and broad SDK support; Google's dedicated parsers are straightforward but priced per document-count increment, which can make short receipts expensive relative to low-cost OCR. ABBYY is more compelling where configurable end-to-end processing, review and enterprise automation integration justify a sales-led platform engagement.
- Practical proof-of-concept should include invoices and receipts from the actual countries, vendors, image conditions, and edge cases (tax, discounts, credits, multi-page invoices, handwritten tips, duplicate totals). Record exact model/API versions and pin versions where available.

### Gaps
- Azure's exact model-specific per-page pricing and ABBYY's commercial terms require a live calculator/quote; prices vary with location, commitments, tiers and volume.
- This comparison does not normalize discounts, taxes, cloud storage/egress, concurrency quotas, SLA, retention, or contract-level data-processing terms.
