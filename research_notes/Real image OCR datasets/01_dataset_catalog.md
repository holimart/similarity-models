# Public Real-Image Scene Text OCR Dataset Catalog

## Which datasets best test difficult real-world OCR, and what does each actually measure?

### Takeaway
For comparing PaddleOCR/RapidOCR as complete OCR pipelines, combine a broad end-to-end set (TextOCR or COCO-Text) with focused detection stress tests (ICDAR 2015, Total-Text, CTW1500, ArT) and language-specific sets (ReCTS/LSVT for Chinese). No single benchmark simultaneously offers large scale, broad scripts, curved text, small/blurred text, public train labels, and standardized recognition evaluation. Keep detection, cropped-word recognition, and end-to-end metrics separate: datasets and official protocols differ substantially.

#### Important corrections and benchmark interpretation

- Use the official COCO-Text project and repository for bibliographic details and data protocol; secondary listings sometimes misattribute publication metadata. [Project](https://bgshih.github.io/cocotext/); [API/repository](https://github.com/bgshih/cocotext).
- There are dataset release variants and inconsistent counts in papers/repos, especially for available transcriptions, “text instances” versus images, strong versus weak labels, and line versus word annotations. Treat the source release and official evaluator as authority; record dataset version and preprocessing in any comparison.
- The STR comparison study documents that inconsistent train/evaluation datasets produce misleading model comparisons, motivating fixed evaluation lists and normalization rules: [Baek et al., ICCV 2019](https://arxiv.org/abs/1904.01906); reference implementation [deep-text-recognition-benchmark](https://github.com/clovaai/deep-text-recognition-benchmark).
- Curved-text detection papers explicitly motivate flexible text-shape datasets such as Total-Text and CTW1500: [CRAFT paper](https://arxiv.org/abs/1904.01941), official [CRAFT repo](https://github.com/clovaai/CRAFT-pytorch).

### Inferences
- Recommended compact suite for an OCR *system* bake-off: ICDAR 2015 (incidental blur/skew), TextOCR (dense real-world word instances), Total-Text or CTW1500 (curves), plus ReCTS/LSVT if Chinese capability is in scope. Add MLT-19 for multilingual breadth.
- To compare detection modules fairly, run on original full-resolution images and report official polygon/box metrics per dataset. To compare recognition, evaluate both supplied word crops and detector-generated crops; the former isolates recognizer quality, the latter captures pipeline errors.
- Report end-to-end precision/recall/H-mean or official script alongside character/word accuracy. State lexicon use, ignored/difficult-region handling, normalization (case, punctuation, Unicode), image resizing, and language model/charset. PaddleOCR and RapidOCR packaging defaults can alter those choices.
- A useful hard-case analysis should stratify matched instances by text pixel height, orientation/curvature, blur/legibility, occlusion, contrast and script. Most named datasets do not expose all these attributes as standardized labels, so condition-specific bins often require additional manual annotation or image-based proxies.

### Gaps
- The COCO-Text arXiv identifier is not confirmed from a primary paper landing page in this research pass; use the linked official project and verify final citation metadata before publication.
- Exact transcribed-instance counts and scripts vary across versions/releases for COCO-Text, ArT, CTW1500, ReCTS and LSVT. The catalog avoids giving unsupported exact transcription totals where the primary source/protocol does not make them unambiguous.
- Dataset access terms, registration, download availability, and test-label visibility can change. Confirm licensing and permitted redistribution before building a shared evaluation package.

## How should the catalog be used to compare PaddleOCR and RapidOCR?

### Takeaway
Use public official test splits as untouched evaluation sets, avoid training on benchmark test imagery, and make the unit of comparison explicit. Benchmark detectors, recognizers, and full pipelines independently because a single end-to-end score cannot identify whether a miss came from localization, crop rectification, recognition, or script support.

### Cited Findings
- Scene text recognition comparisons are confounded by inconsistent dataset choices and evaluation protocols; a unified framework was proposed to improve comparability. [Baek et al., ICCV 2019](https://arxiv.org/abs/1904.01906)
- CRAFT detection uses character-region and affinity modeling and demonstrates the utility of flexible localization on arbitrarily oriented/curved text. [Baek et al., CVPR 2019](https://arxiv.org/abs/1904.01941); [official code](https://github.com/clovaai/CRAFT-pytorch)
- Official dataset challenge sites provide their own split definitions, annotations, and evaluators: [ICDAR RRC](https://rrc.cvc.uab.es/), [Total-Text](https://github.com/cs-chan/Total-Text-Dataset), [TextOCR](https://textvqa.org/textocr/), [LSVT](https://rrc.cvc.uab.es/?ch=16).

### Inferences
- Suggested reporting matrix: detection-only (official localization metric), recognition-only (fixed provided crops, exact-match/normalized edit distance), end-to-end (official matching plus transcription), throughput/latency on stated hardware, and robustness slices.
- Include OCR engine/model versions, detector and recognizer language packs, image resize limits, confidence thresholds, angle classification, and any document/line postprocessing. Otherwise framework defaults rather than core model behavior may explain differences.

### Gaps
- Public benchmark formats are heterogeneous; a carefully validated conversion layer is needed before aggregating scores. No cross-dataset unified evaluator resolves polygon matching, ignored regions, lexicons, and Unicode normalization across all listed sets.
