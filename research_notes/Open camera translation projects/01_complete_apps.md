# Open camera translation projects

## Which open projects implement a live-camera translation experience, and how complete are they?

### Takeaway

The clearest Google-Translate-camera-style match found is [crlx1q/ar-camera-translate](https://github.com/crlx1q/ar-camera-translate): an Android Flutter app that claims continuous camera OCR, on-device translation, and location/rotation-aligned translated text. Other repositories advertise real-time camera translation but expose much less evidence of a polished, anchored AR replacement experience. Hearth is an actively developed Android app with meaningful camera OCR and translation, but its camera path is camera/photo OCR; its live overlays apply to speech captions and screen/manga translation, not a live physical-world camera feed.

### Cited Findings

- **Closest AR/live-camera match — ar-camera-translate (Android/Flutter).** The repository README describes real-time Google ML Kit camera text recognition, automatic source-language identification, on-device/offline translation across English, Russian, Spanish, French, German, Italian, Portuguese, Chinese, Japanese, and Korean, and translations rendered over the source text anchored to its position and angle. It offers Android APK builds through GitHub Actions/releases and describes selecting an APK artifact and installing it on a device. [Project README](https://github.com/crlx1q/ar-camera-translate)
- Its README explicitly warns that bundled ML Kit OCR only recognizes Latin, Chinese, Japanese, Korean, and Devanagari scripts; Cyrillic and Arabic are not recognized by camera OCR, although Russian is a supported target translation language. This important distinction limits its practical source-language coverage. [Project README](https://github.com/crlx1q/ar-camera-translate)
- GitHub lists 24 commits, no releases visible on the repository landing page, zero stars/forks, and no listed license file/resource. The README's APK download path is through Actions artifacts or Releases; I did not verify a current public artifact or execute the app. [Repository status/files](https://github.com/crlx1q/ar-camera-translate)
- **Hearth (Android/Kotlin; Apache-2.0 first-party code) — active but adjacent rather than camera AR.** Its current README describes an experimental proof of concept, live speech captions with floating overlays, screen/manga translation, and a separate camera/imported-photo OCR translation feature. It expressly says screen translation has no artwork inpainting or frame-perfect tracking; that is screen capture, not live camera AR. Its camera OCR examples are shown as local OCR and translation rather than translated text anchored over a live camera preview. [Project README](https://github.com/Sal7one/Hearth)
- Hearth provides downloadable ARM64 preview APKs (cloud+local and offline-only), says Android 9+ and Android 10+ for device-audio capture, and documents local and cloud service setup. OCR options include PaddleOCR, Manga OCR, and Meiki; translation options include HY-MT1.5/Hy-MT2, TranslateGemma 4B, Marian bundles and, in the cloud-capable build, ML Kit; cloud translators include Google Cloud, Azure, DeepL, and LibreTranslate. Language availability depends on selected engine/model, not a fixed app-wide language list. [Project README](https://github.com/Sal7one/Hearth)
- Hearth warns it is not production-ready and that accuracy, language coverage, and speed depend on model/provider/device. Its repository page shows 118 commits, a current release reference v0.22.3, Apache-2.0 first-party code, and third-party model/runtime terms. A release and repository are project-primary evidence, not independent validation of quality. [Project README/status](https://github.com/Sal7one/Hearth); [license](https://github.com/Sal7one/Hearth/blob/main/LICENSE); [third-party notices](https://github.com/Sal7one/Hearth/blob/main/THIRD_PARTY_NOTICES.md)
- **VISION_Sense (Android/Java) — older real-time camera claim, cloud-dependent.** The author describes an Android app translating text from images or video and claims real-time camera translation among 200+ languages using Google Cloud APIs and OCR. The repository includes an Apache-2.0 license, but only two commits are shown and the repository search result indicates it was last updated in 2017. README/repository content does not establish word-box overlays, inpainting, offline support, or a maintained/demo-ready app. [Project README and status](https://github.com/Akarsh-TS/VISION_Sense); [license](https://github.com/Akarsh-TS/VISION_Sense/blob/master/LICENSE)
- **Live-Text-Translator (Android/Kotlin) — camera-preview claim, sparse evidence.** README says to point the camera at text to view a translation and calls it real-time translation through the camera preview. It has 22 commits but the repository page exposes no license, releases, language list, implementation details, setup instructions, or screenshots sufficient to verify how translation is displayed or whether it remains aligned to detected text. Treat as a potentially relevant prototype, not evidence of complete AR replacement. [Project README/status](https://github.com/gSrikar/Live-Text-Translator)
- **Lunga (Android/Kotlin/Jetpack Compose) — camera capture/recognition, not confirmed live overlay.** README describes camera text recognition, ML Kit language ID, 20+ language translation, and MyMemory Translation API; its tech stack calls out CameraX and ML Kit OCR, while listing offline mode as an upcoming feature. It describes image/camera text translation but does not confirm continuous OCR on preview or source-anchored translations. README badge claims MIT, but the landing-page file list does not show a LICENSE file; verify repository terms before reuse. [Project README/status](https://github.com/klaus19/Lunga)
- **MentraOS Camera Translate (smart glasses + companion setup) — capture-and-translate, not continuous AR overlay.** This small TypeScript app uses MentraOS Camera API to take photos and translates text in them using OpenAI API; setup requires MentraOS, app registration, Bun, an ngrok public URL, MentraOS API key, and OpenAI API key. Its documented mechanism is photo capture, and no OCR language matrix/offline option or continuously tracked translated text is claimed. It has an MIT license. [Project README](https://github.com/martykan/mentraos-camera-translate); [license](https://github.com/martykan/mentraos-camera-translate/blob/main/LICENSE)
- **Other lower-evidence leads:** [Photolate](https://github.com/ACatalin14/Photolate) describes an Android app to detect/translate real-time text using the camera, but its repository page reveals six commits and no visible license or detailed feature/setup documentation; [the8bitpanda/lens](https://github.com/the8bitpanda/lens) describes real-time Android camera translation alongside text actions, but the checked repository landing page has no README content or explicit license and does not establish an AR overlay pipeline. These are leads, not verified feature-complete choices.
- **Web/PWA lead — philipposk/translator.** The public repository describes a Next.js PWA with live voice, text, file, and camera translation, and links to a Vercel-hosted app. The inspected landing-page output did not include implementation/README, language, camera-preview behavior, OCR/overlay method, offline support, or license information. Do not classify it as live-camera AR based on the repository description alone. [Repository](https://github.com/philipposk/translator); [linked demo](https://audio2text-seven.vercel.app)
- Repository search produced additional camera translator claims (including [InstaTranslate](https://github.com/zelayakevin92-max/InstaTranslate), advertising iOS/Android and 18+ languages), but available repository discovery snippets alone do not establish code completeness, actual live overlay behavior, license, or working demo; omitted from positive feature assessment. [GitHub repository search](https://github.com/search?q=real-time+camera+translation+android&type=repositories)

### Inferences

- There is at least one plausible open Android prototype specifically attempting tracked translation over live camera text, but it is very small/unproven and OCR-script gaps conflict with its advertised 10 translation languages. It merits direct device testing before being considered a usable or robust reference implementation.
- Many repo descriptions use “real-time” loosely: evidence of image capture, video text processing, a camera preview, OCR or translation alone does not establish the full Translate-camera interaction (continuous live feed + aligned translated overlay, with the original obscured/replaced).
- None of the reviewed primary sources independently demonstrates quality through a separately maintained benchmark or third-party hands-on evaluation. GitHub README screenshots and feature lists are self-reported; no independent device verification was available in this research pass.

### Gaps

- For ar-camera-translate, exact build prerequisites, model download/storage behavior, per-language source OCR capabilities beyond its stated script list, frame rate/latency, text tracking stability, and background removal/inpainting behavior are not specified in the inspected README. No independent APK execution or external evaluation was found.
- For VISION_Sense, actual current Google API requirements, credentials/billing, supported source/target languages in implementation, camera overlay UX, and whether it can still build against present Android tooling need code/build inspection and testing.
- For Live-Text-Translator, Photolate, and Lens, the inspected repository pages do not provide enough evidence about licenses, OCR/translation services, language coverage, offline operation, installation/demo route, or overlay behavior.
- For the PWA lead, whether “camera translation” uses a live stream or captured still image, whether any translation is spatially overlaid, and the license/translation backend remain unverified.

## Which complete or near-complete apps and implementation patterns are worth distinguishing from the target experience?

### Takeaway

For a practical project shortlist, evaluate ar-camera-translate as the strongest exact camera-AR prototype and Hearth as a much better-documented offline-capable Android translation/OCR app whose live overlay features serve different input modes. Treat older Android apps and smart-glasses or web projects as adjacent implementations unless code or a working demo proves continuous source-anchored text overlays.

### Cited Findings

- Google's ML Kit on-device translation and text recognition are the central claimed components of ar-camera-translate, while its README explicitly restricts OCR input scripts; it uses app-level overlay positioning/rotation, not documented image inpainting. [Project README](https://github.com/crlx1q/ar-camera-translate)
- Hearth's most fully documented overlays are Android floating UI for translated speech captions and screen reading. Its README describes screen/manga translation as experimental, manual/settled-page refresh, and no inpainting or frame-perfect tracking; camera OCR remains a separate camera/photo text recognition-and-translation feature. [Project README](https://github.com/Sal7one/Hearth); [screen-reading guide](https://github.com/Sal7one/Hearth/blob/main/docs/screen-reading.md); [camera OCR guide](https://github.com/Sal7one/Hearth/blob/main/docs/camera-ocr.md)
- For offline constraints, Hearth explicitly offers an offline-only ARM64 APK with no network permission and local model imports, alongside cloud-capable mode; ar-camera-translate claims fully on-device OCR/translation without API keys. [Hearth README](https://github.com/Sal7one/Hearth); [ar-camera-translate README](https://github.com/crlx1q/ar-camera-translate)
- VISION_Sense's own description relies on Google Cloud API; Lunga names MyMemory Translation API and identifies offline as upcoming; MentraOS Camera Translate requires OpenAI credentials. Their self-reported architecture therefore signals network/service dependence rather than a self-contained offline translator. [VISION_Sense](https://github.com/Akarsh-TS/VISION_Sense); [Lunga](https://github.com/klaus19/Lunga); [MentraOS Camera Translate](https://github.com/martykan/mentraos-camera-translate)
- Licenses differ and must be checked per repository: ar-camera-translate and Live-Text-Translator show no license resource on inspected repository pages; VISION_Sense is Apache-2.0; Hearth's first-party code is Apache-2.0 with separate third-party/model terms; MentraOS Camera Translate is MIT; Lunga's MIT badge is not corroborated by a visible root LICENSE on the checked page. [Repositories: ar-camera-translate](https://github.com/crlx1q/ar-camera-translate), [Live-Text-Translator](https://github.com/gSrikar/Live-Text-Translator), [VISION_Sense](https://github.com/Akarsh-TS/VISION_Sense), [Hearth](https://github.com/Sal7one/Hearth), [MentraOS Camera Translate](https://github.com/martykan/mentraos-camera-translate), [Lunga](https://github.com/klaus19/Lunga)
- Independent verification: no independent app-store listing, maintained third-party review, or external technical evaluation establishing real-world overlay accuracy was found for the closest match. The primary-source evidence supports feature claims only; repository activity/release metadata provides a basic status signal, not proof of working behavior. [ar-camera-translate](https://github.com/crlx1q/ar-camera-translate); [Hearth](https://github.com/Sal7one/Hearth)

### Inferences

- For a prototype evaluation, distinguish three technically separate layers: repeated OCR on camera frames; translation triggered efficiently with language/model management; and stable camera-coordinate mapping of translated text. The README of ar-camera-translate asserts all three but only source-level inspection/device testing could verify their implementation quality.
- Overpainting the original text is not equivalent to inpainting: the target project claims overlay positioning/rotation, while none of the reviewed camera-AR evidence establishes background reconstruction to erase source lettering.
- A robust comparison should record source script and language-model coverage separately, because “10 target languages” does not mean OCR can read those languages as source text.

### Gaps

- No hands-on independent tests, latency measurements, device compatibility matrix, accuracy benchmark, or app-store availability was verified for the projects assessed.
- Complete source-code audit of camera frame processing, OCR throttling/debouncing, coordinate transforms, translation caching, and overlay rendering is outside the inspected README-level evidence; needed to confirm how closely the exact-match project behaves like Google Translate camera mode.
- Non-GitHub app distribution and independently maintained forks may exist beyond the scoped repository/project-source search; no claim of exhaustive global coverage is made.
