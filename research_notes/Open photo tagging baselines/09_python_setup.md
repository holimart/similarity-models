# Minimal isolated Python setup for local image-tagging baselines

## Which Python and environment should be used?

### Takeaway

Use a fresh per-baseline `venv` and Python 3.12 as the conservative common choice. Transformers documents Python 3.10+ and PyTorch 2.5+; Python 3.12 is in active security support as of this note, while 3.13/3.14 are newer options that should be checked against the selected PyTorch wheel and platform before standardizing.

### Cited Findings

- Transformers installation documentation says it is tested with Python 3.10+ and PyTorch 2.5+. — [Transformers installation](https://huggingface.co/docs/transformers/installation)
- Python 3.12 is in security-fix status; 3.13 and 3.14 are in bugfix status, and 3.10 is scheduled to reach end of life in October 2026. — [Python Developer’s Guide: Status of Python versions](https://devguide.python.org/versions/)
- OpenCLIP recommends first creating a virtual environment and upgrading pip, then installing `open_clip_torch`; inference usage is shown with `open_clip.create_model_and_transforms`. — [OpenCLIP README](https://github.com/mlfoundations/open_clip)

### Inferences

- Python 3.12 is a practical shared baseline for both libraries: it clears the documented Transformers floor without choosing the newest interpreter version, where wheel availability may vary by platform and torch release.
- Create the environment outside the legacy project environment or in a clearly separate baseline directory. A venv isolates package installation; avoid installing baseline packages into the legacy project's interpreter.

### Gaps

- Exact wheel compatibility depends on operating system, architecture, Python patch release, and the chosen PyTorch/CUDA build; the PyTorch selector should be consulted at installation time.

## Minimal pip installs for CPU and NVIDIA CUDA

### Takeaway

Install PyTorch first using the official selector’s CPU or CUDA-specific command, then install exactly one model API (`transformers` or `open_clip_torch`) plus Pillow. Keep the two model stacks in separate environments if minimizing dependency interactions is more important than sharing dependencies.

### Cited Findings

- PyTorch’s official “Start Locally” page selects install commands based on OS, package manager, language, and compute platform, including CPU and CUDA options. — [PyTorch: Get Started Locally](https://pytorch.org/get-started/locally/)
- Transformers documents pip installation, a CPU-only PyTorch wheel index (`https://download.pytorch.org/whl/cpu`), and NVIDIA GPU installation contingent on using the appropriate PyTorch CUDA build and drivers. — [Transformers installation](https://huggingface.co/docs/transformers/installation)
- OpenCLIP documents inference installation as `pip install open_clip_torch`, and its usage example loads a pretrained model and image transforms. — [OpenCLIP README](https://github.com/mlfoundations/open_clip)

### Inferences

- Run these commands in a shell with Python 3.12 available. Substitute the active Python executable if `python3.12` is named differently:

```bash
python3.12 -m venv .venv-tagging
source .venv-tagging/bin/activate  # Windows: .venv-tagging\Scripts\activate
python -m pip install --upgrade pip
```

- CPU-only environment for a Transformers pipeline/model baseline:

```bash
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install transformers pillow
```

- CPU-only environment for OpenCLIP:

```bash
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install open_clip_torch pillow
```

- NVIDIA CUDA environment: install the PyTorch command generated by the official selector for the machine’s OS and desired CUDA runtime, then install the chosen library. The selector-generated command should be copied as-is; do not assume a CUDA index/runtime string from an old project or old note:

```bash
# First: run the matching command from https://pytorch.org/get-started/locally/
python -m pip install transformers pillow
# OR, in an OpenCLIP environment:
python -m pip install open_clip_torch pillow
```

- Validate the selected PyTorch backend before downloading model weights:

```bash
python -c "import torch; print(torch.__version__); print('CUDA available:', torch.cuda.is_available())"
```

- `transformers` and `open_clip_torch` are alternatives for this minimal setup, not mandatory joint requirements. For OpenCLIP inference the documented core install is the package itself; `pillow` supplies straightforward image loading. Add other dependencies only when a chosen model/example actually needs them.

### Gaps

- The PyTorch selector is dynamic; this note does not freeze a torch version or CUDA runtime because the correct choice depends on the target host and current official wheel matrix.
- Transformers model loading APIs and additional optional image-processing dependencies can differ by model family; install model-specific extras only after selecting the checkpoint.

## Keeping the baseline isolated from legacy project dependencies

### Takeaway

Use a new venv with its own pip, and invoke pip as `python -m pip` after activation. Do not reuse or upgrade the legacy environment: the baseline’s torch, torchvision, transformers, and related transitive dependencies may conflict with pinned application packages.

### Cited Findings

- Transformers recommends a virtual environment to manage different projects and avoid dependency compatibility issues. — [Transformers installation](https://huggingface.co/docs/transformers/installation)
- OpenCLIP’s install instructions likewise advise creating a virtual environment before installing the package. — [OpenCLIP README](https://github.com/mlfoundations/open_clip)
- The Python standard library provides `venv` for creating lightweight virtual environments with isolated site-package directories. — [Python `venv` documentation](https://docs.python.org/3/library/venv.html)

### Inferences

- Record the environment recipe alongside baseline code (Python version, torch install command, and package list); use a separate venv per backend when comparing or troubleshooting.
- After a working install, capture resolved versions with `python -m pip freeze` so a later rerun can reproduce the package set. A freeze file is an environment record, not a substitute for selecting the correct platform-specific PyTorch wheel.

### Gaps

- No project-specific legacy dependency lockfile was assessed here; therefore, no concrete package conflict or exact separation path inside the repository can be asserted.
